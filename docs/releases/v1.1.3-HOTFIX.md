# SAE v1.1.3 HOTFIX — Release Notes

**Tipo de Lanzamiento**: Mantenimiento Crítico & Hotfixes de Arquitectura Híbrida  
**Estado**: Estable para Producción

Esta versión menor es un "Hotfix" orientado a **resolver problemas críticos en la carga de variables nativas en el sistema operativo Windows**, y a resolver la problemática de las colisiones de puertos en aquellos dispositivos de instituciones educativas que contengan otras bases de datos como XAMPP o servidores ocupando el rango tradicional `5000`.

Adicionalmente se soluciona un problema silencioso en el modo de empaquetado de backend en procesamientos locales donde variables externas de `C++` o librerías dinámicas DLL como (*Prisma SQLite Engine*) requieren la ejecución estática de NodeJS en segundo plano.

---

## 🛠️ Novedades y Correcciones Críticas

### 1. Sistema Dinámico Anti-Colisión de Puertos (Dynamic Port Orchestrator)
- **Problema previo**: Si el dispositivo escolar corría cualquier aplicación en el puerto `http://localhost:5000/`, SAE colapsaba y el frontend cargaba roto e imposibilitado de conectarse a Prisma.
- **Solución (1.1.3)**: Implementación de Módulo Dinámico en `electron/main.js` (`net.createServer`) que negocia un puerto disponible libre y aleatorio (Ej. `51802`) con Windows en microsegundos y se lo asigna sincrónicamente al Frontend a través de la inyección Hash en la URL de Chromium (`#apiPort=51802`).

### 2. Standalone Node.js Fallback Integrado
- **Problema previo**: Se dependía de `ELECTRON_RUN_AS_NODE` que causaba inconsistencias entre entornos con Prisma si un entorno local no contenía una instalación tradicional de las variables internas de C++.
- **Solución (1.1.3)**: Se reactivó la directiva manual de carga de empaquetado y se priorizó en el código nativo: `require('fs').existsSync(...) ? customNode : process.execPath`. Ahora la configuración en `build.extraResources` despacha nativamente el `node.exe` empaquetado para estabilizar el orquestador principal.

### 3. Centralización Avanzada de Logs
- **Problema previo**: El módulo pino duplicaba logs al `stdout` lo causaría desbordamientos y memory leaks potenciales si el usuario manipulaba mucha información.
- **Solución (1.1.3)**: Integración oficial de `electron-log/main`. Sistema de *File Rotation* instaurado. Ahora SAE almacena bitácoras con límite máximo estricto de **10 MB** en `%APPDATA%\SAE\logs\main.log`. Se optimizó la mitigación de expresiones regulares de Pino incrementando sustancialmente el rendimiento del Event Loop.

### 4. Telemetría Aumentada
- El log en tiempo real captura automáticamente ahora la **Arquitectura, Versión OS, Memoria** y el **Puerto Activo Asignado** cuando el servidor se lanza, para facilitar las auditorías técnicas remotas y soporte TI.

---

## 📋 Archivos Clave Modificados

- `package.json` & `frontend/package.json`: Control de versiones y semver (*1.1.3-HOTFIX*).
- `electron/main.js`: Implementación de Detección de puertos y el motor de Node de 89mb empaquetado local.
- `frontend/src/api/client.js` & `frontend/src/App.jsx`: Refactorización de Axios y `getBaseUrl` para lectura e interrupción nativa mediante variables de SessionStorage y Hash Injection de URLs estáticas (`file://`).
- `backend/utils/logger.js` & `backend/middlewares/requestLogger.js`: Mitigación Anti-Bloqueos al emplear el hook `.on('finish')` reemplazando los parches a `res.send()`.
